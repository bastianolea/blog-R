## Estructura propuesta del tutorial

1. **Introducción y motivación** — por qué tener un blog propio: soberanía digital, portafolio, aprender haciendo, reciprocidad con la comunidad de R (usar la idea de la cita del taller sobre que "aprendimos todo por internet", reformulada a mi estilo). Breve mención de que es 100% gratuito.

2. **Herramientas que usaremos** — Quarto (con nota de que es sucesor de R Markdown), RStudio, Git, GitHub, GitHub Pages. Tabla o lista breve de qué hace cada una.

3. **Configurar Git y GitHub** (autosuficiente, no solo enlazado)
   - Qué es Git y qué es GitHub (diferencia).
   - Instalar `{usethis}`.
   - `usethis::use_git_config()`.
   - Crear token con `usethis::create_github_token()` y guardarlo con `gitcreds::gitcreds_set()` (incluir la aclaración del taller de por qué no se muestra el token en pantalla).
   - `usethis::git_sitrep()` para confirmar configuración.
   - Nota: dejar clara la dependencia de orden (configurar antes de intentar `use_github()`, error común mencionado en el taller).

4. **Crear el proyecto Quarto Blog**
   - File → New Project → New Directory → Quarto Blog.
   - Estructura de archivos generada (diagrama de árbol, tomado de las diapositivas): `_quarto.yml`, `index.qmd`, `about.qmd`, `posts/`, `profile.jpg`/imagen de perfil, `styles.css`.
   - Primer render/preview para confirmar que funciona.

5. **Diferencia entre `quarto preview` y `quarto render`**
   - Explicar con las palabras aclaratorias del taller: preview = servidor vivo que se actualiza solo; render = reconstrucción completa del sitio, necesaria antes de publicar.
   - Mostrar ambas formas: terminal (`quarto preview` / `quarto render`) y R (`quarto::quarto_preview()` / `quarto::quarto_render()`).

6. **Escribir publicaciones**
   - Cómo crear una publicación nueva: carpeta dentro de `posts/` con `index.qmd` (manual, la forma que Bastián prefiere) y alternativa con `quarto::new_blog_post("Título")`.
   - Convención de nombres de carpetas: sin espacios, sin mayúsculas, con guiones o guion bajo (mencionado en el taller como causa de errores/URLs feas).
   - Encabezado YAML de una publicación: `title`, `subtitle`, `author`, `date`, `categories`, `image`. Aclarar el error común de dejar el front matter sin cerrar con `---`.

7. **Sintaxis Markdown básica** — títulos, negritas, itálicas, listas, enlaces, imágenes, notas al pie, subrayado, tachado (tomado de las diapositivas).

8. **Código de R en las publicaciones**
   - Bloques de código (chunks), opciones más usadas: `echo`, `eval`, `warning`, `message`, `error`, `fig-height`.
   - Aclarar que todos los chunks de un documento comparten el mismo entorno (pregunta real del taller sobre dónde poner los `library()`).
   - Código de R en línea (*inline*) con ejemplo de párrafo que se autocompleta con un valor calculado (ejemplo del taller: "la correlación es alta/baja según el valor").
   - Nota de estilo: en los chunks de ejemplo con `library(dplyr)` u otro paquete que imprime mensajes, usar `#| message: false` y `#| warning: false`.

9. **Personalizar el sitio**
   - Cambiar el tema del `_quarto.yml` (temas Bootswatch predefinidos).
   - Configurar el menú de navegación (`navbar`), agregar páginas, agregar íconos de redes sociales (Font Awesome: `github`, `linkedin`, etc.), mencionar que se pueden usar imágenes propias para íconos no incluidos (ej. Slack, Meetup).
   - Título y descripción del sitio.

10. **Personalización avanzada con SCSS**
    - Crear archivo `tema.scss` y referenciarlo en `_quarto.yml` junto al tema base.
    - Variables SCSS más comunes (colores primario/secundario, fondo, texto, enlaces, bordes, navbar).
    - Tipografías con Google Fonts: buscar fuente → "Get embed code" → `@import` en el `.scss` → aplicar con `$font-family-sans-serif` y selectores de encabezados.
    - Mencionar el uso del inspector del navegador (clic derecho → inspeccionar) para encontrar clases y probar cambios de CSS antes de escribirlos.
    - Aclarar la duda real del taller sobre tamaño de letra: markdown no controla estilos, eso se hace aparte con CSS/SCSS.

11. **Preparar el sitio para GitHub Pages**
    - Agregar `output-dir: docs` bajo `project:` en `_quarto.yml`.
    - Crear archivo vacío `.nojekyll`.
    - Ejecutar `quarto render` para reconstruir todo antes de publicar.

12. **Subir el proyecto a GitHub**
    - `usethis::use_git()` para crear el repositorio local.
    - `usethis::use_github()` para crear el repositorio remoto y subirlo.

13. **Publicar en GitHub Pages**
    - En GitHub: Settings → Pages → seleccionar rama (`main`) y carpeta `/docs` → Save.
    - Esperar a que el sitio se genere (indicador de estado).
    - Obtener la URL pública (`https://usuario.github.io/repositorio`), y el truco de nombrar el repositorio `usuario.github.io` para tener la URL raíz.

14. **Actualizar el blog en el futuro** — flujo de mantenimiento: editar contenido → `quarto render` → `git add .` → `git commit -m "..."` → `git push` (o usar el panel Git de RStudio en vez de la terminal). Aclarar que solo se sube lo modificado y que el sitio se actualiza solo en 1-2 minutos.

15. **Preguntas frecuentes** (extraídas de las preguntas reales del taller, redactadas como mini-FAQ):
    - ¿Es realmente gratis?
    - ¿Alguien puede "robarse" mi blog si el código es público? (repos públicos vs. privados y su limitación con GitHub Pages).
    - ¿Se puede hacer un layout tipo libro con barra lateral? (mención breve de `website: sidebar:` y de que para libros extensos conviene revisar Bookdown/Quarto Books).
    - ¿Cómo cambio el tamaño de letra del texto?
    - Errores comunes: front matter mal cerrado, indentación incorrecta en YAML, token de GitHub que falla por no correr `use_git_config()` antes.

16. **Cierre y recursos** — invitación a compartir el blog resultante, enlaces a: tutorial de Git con R (`happygitwithr.com` o el propio tutorial de GitHub del blog), documentación oficial de Quarto websites/blogs, temas Bootswatch, variables SASS. Créditos al taller y al grupo de usuarios de R de Santiago de Chile que lo organizó. Shortcode `{{< cafecito >}}` al final, como es habitual.

## Consideraciones de estilo (de la skill `estilo-escritura`)

- Sin artículos en encabezados de sección ("Configurar Git y GitHub", no "La configuración de Git...").
- Palabras en inglés en itálica (*commit*, *push*, *token*, *preview*, *render*, *front matter*, etc., salvo nombres propios de comandos/funciones que van en `code`).
- Lenguaje inclusivo donde corresponda.
- Negritas con moderación (máximo una vez por párrafo, solo para pasos realmente importantes).
- Comentarios de código en minúsculas.
- Usar "ñ" en nombres de variables de ejemplo si corresponde (ej. si se muestra una variable de año).
- Enlazar generosamente a publicaciones anteriores del blog relacionadas (tutorial de Git/GitHub, tutorial de reportes Quarto, tutorial de Shiny si se menciona apps).
- Antes de cada bloque de código, explicar qué se hará; después, comentar el resultado si aplica.
- Emojis solo al final de la publicación o para mostrar un antes/después.
